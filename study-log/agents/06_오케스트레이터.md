# Concept
- Pier Communication
  - 중앙 오케스트레이터 통한 통신 병목 방지
  - TeamCreate, TaskCreate, SendMessage

# 리더는 이벤트 루프
- 이벤트에 반응
- 메세지 및 산출물 최종 통합, 유휴 알림(콜백), 에러 처리 등의 역할 수행
  - 로그 중앙화 및 모니터링하다가 품질/비용/에이전트 이슈 임계치 넘어서면 개입
    - PostToolUse로 컨텍스트 소모없이 append-only json logging
  - 에이전트간 역할/약속이 어긋나는 경우 개입
    - 메세지, 작업큐, 파일 공유, 최종 산출물 등 기대 입출력/행동이 다른 경우
    - 주요 Phase 후 QA checkpoint 도입으로 보통 해결 

# 주요 도구
## 세션 초기 팀 구성
- TeamCreate + AgentTool
- 세션 시작할 때 리더가 호출해서 메모리내 생성 후 세션과 함께 종료
- 팀 생성, 역할부여, 통신 대상 정의
## 작업 분할
- TaskCreate, TaskUpdate 공유 작업 큐
- 병렬 수행 가능한 건 동시 처리, depends_on있으면 전제 작업 완료 대기, 팀원들을 TaskList로 직접 큐 읽고 TaskUpdate로 직접 작업 가져감.
- 리더는 TaskGet으로 전체 진행률 확인
## 상호 참조/공유 등 팀원간 짧은 통신
- SendMessage
- to (팀원 이름), summary (수신자에게 보이는 한 줄 요약), message (본문)
- 에이전트 정의 파일 내 팀 통신 프로토콜
## 중간 산출물 교환
- 대용량/단계간 인계를 위한 파일 규약 (_workspace/*.md)

# TeamDelete
- 세션 당 팀 하나 이므로 파라미터 없이 자동으로 활성화 팀 삭제
- shutdown_request 통해 에이전트 정리 대기
- _workspace는 삭제 이후에도 유지

# 안티패턴
- shutdown 없이 TeamDelete 호출
  - 에러 처리없이 세션 종료시 파일 락이 남아 다음 세션에서 해당 파일 사용X
  - 팀원들에게 모두 shutdown_request -> 팀원들이 모두 shutting_down TaskUpdate 응답 -> TeamDelete
- 리더가 모든 결정 독점

  - 리더 메일함 점유율 < 40%와 같이 모니터링
- 브로드캐스트 남발
  - 필요한 메세지 우선순위 밀려나는 문제
