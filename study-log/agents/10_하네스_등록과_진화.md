# Overview
- 스킬 생성 후 CLAUDE.md에 등록하지 않으면 첫 세션 이후 하네스 호출X
- 새 세션에서 하네스가 자동으로 트리거되는 4층 재호출 구조, 드리프트 신호

# 하네스 7계층
- CLAUDE.md > skills > subagnets > Agent teams > hooks > mcp > plugins
  - CLAUDE.md는 0계층이자 유일하게 항상 활성화

# CLAUDE.md 4단계 스코프 계층 & 하네스 포인터 위치
- 적용 우선순위  
  - 구체적인 것이 일반적인 것을 덮어씀
  - 조직 > 디렉토리 > 프로젝트 > 사용자
- 하네스 포인터 정식 위치는 프로젝트(공유 가능한 인프라)

# 하네스 등록
- CLAUDE.md내 하네스 포인터(섹션) 구성
  - 하네스명, 목표, 트리거, 변경이력
  - 트리거가 있어야 오케스트레이터가 어던 요청에서 스킬을 호출할지 결정 가능
- 금지 목록(중복)
  - 에이전트 목록, 스킬 목록, 디렡노리구조, 실행규칙 상세

# Phase 0 현황 감사와 7-5 운영 루프
## Drift 종류
- 에이전트 drift
  - 도구 반복 호출시 결과 품질 저하
- 구조 drift
  - 기존 에이전트/스킬목록과 CLAUDE.md 기록간 불일치
## Phase 0  
- 모든 하네스는 트리거가 잡히면 기존 하네스 현황 확인 후 실행모드 분기함
  - 신규 구축: 에이전트/스킬 디렉토리가 없거나 비어있음 -> Phase1부터 전체실행
  - 기존 확장: 기존 하네스에 새 에이전트/스킬 추가 -> 필요 Phase만 진행
  - 운영/유지보수: 기존 하네스 감사/수정/동기화 -> Phase7-5
## Phase 7-5
- Step1. .claude/agents,skill 이하 실제 목록과 오케스트렝터 스킬 내 agents,skill의 불일치 목록 생성, 감사 결과 사용자 보고
- Step2. 사용자 요청 별 agents,skill 추가/수정/삭제 진행 한 번에 하나씩 수행하며, 각 변경 후 즉시 Step3(동기화)
- Step3. CLAUDE.md의 변경 이력 테이블에 날까/변경내용/대상/사유 기록
- Step4. 변경 검증(실행테스트, 드라이런 등), CLAUDE.md와 실제 파이르이 일치여부 최종 확인
## Phase 7-1 ~ 7-4
- 피드백 수집
 - 사용자에게 결과 개선할 부분 있는지, 에이전트 팀 구성/워크플로에서 변경할 부분있는지 질문
- 반영 대상 매핑
  - 받은 피드백을 어디에 반영할지 결정(표 참고)
- 실수가 재발하지 않도록 과거의 실패 교정 내용을 기록
  - 변경 이력 내 사유에 따라 나중에 불칠요해지면 해당 에이전트/스킬 삭제
- 왜 쓰지 않는가 질문
  - 하네스 개선 신호(반복 피드백, 반복 실패, 우회 관찰-호출 빈도 하락 등 제 기능X)
 
# (부분)재실행
- 진화된 하네스를 오케스트레이터가 올바르게 재싱핼하도록 하기
  - description에 재실행용 키워드 주입
  - Phase1 워크 스페이스 확인
    - _workspace/ 없거나 새 입력 제공시 Phase1부터 실행, 부분 수정 요청시 재실행

# 기타
## Phase7-3 ADR 변경 이력 관리
- 아키텍쳐 결정의 배경과 트레이드오프 기록문서
  - 상태(활성 여부), 맥락(결정 필요 배경), 결정 사항, 결과(수용한 트레이드오프), 삭제 조건(언제 이 결정이 불필요해지는가, build_to_delete)
## 안티패턴
- CLAUDE.md가 너무 정보가 많으면 구성 불일치/캐시 미스/인지 과부하 유발됨
  - 경로별 상세규칙은 .claude/rules/로 이전
- 재실해용 키워드가 description에서 빠지면 트리거 있어도 재실행 안 됨
- HTML 주석은 삭제되어 컨텍스트 렌더링됨
- 에이전트/스킬 수정되는데 변경이력 업데이트 누락
  - git hook 강제
